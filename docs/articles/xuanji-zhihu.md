## 先说痛点

做 AI 应用的人基本都经历过这些事：

- 手上有 **硅基流动、商汤、DeepSeek 中转、各种免费渠道** 五六个 API Key，工具里来回切，改一个模型配置要动好几个文件；
- Claude Code / OpenCode / 各类 Agent 框架，每家只认 OpenAI 协议或 Anthropic 协议，渠道多了根本没法统一；
- 某家上游**半夜抽风**，请求批量失败，你第二天起来看日志才发现昨晚的工作流全断了；
- 付费渠道和免费渠道混在一起，没有调度逻辑，白嫖额度永远用不完，付费账单倒是先爆了。

市面上不是没有网关——OneAPI、New-API 都是成熟方案。但用下来有几个别扭的地方：

1. **重**：Go 单二进制但功能堆得重，Docker 镜像 ~200MB，还要配套 MySQL/Redis，个人服务器上光伺候它就够呛；
2. **协议兼容差**：流式 SSE 丢行、工具调用字段丢失、多模态 content 结构被拆坏，OpenAI 兼容做得好的，Anthropic 又不行；
3. **冷启动配置**：改配置要重启，或者 API 调用链巨长，运维心智负担重。

于是我自己写了一个。

## 璇玑 Xuanji 是什么

一句话：**Go 单二进制的 AI 协议网关**，为 Hermes、Claude Code、OpenCode 等 AI 工具提供一个统一入口，汇聚多家上游，按成本与健康状态自动分流。

名字取自北斗第一星——古代天文仪器的轴心枢纽，汇聚万向、运转分流。

## 硬核点一：双协议原生，不是"翻译"是"透传"

大多数网关只做 OpenAI 协议，Anthropic 协议要靠一层"翻译"——翻译就必然有损。

璇玑的做法是 **双协议原生实现**：

| 协议 | 端点 | 说明 |
|------|------|------|
| **OpenAI** | `POST /v1/chat/completions` | 聊天补全（流式/非流式） |
| | `POST /v1/embeddings` | 文本嵌入 |
| | `POST /v1/images/generations` | 图片生成 |
| | `POST /v1/rerank` | 重排 |
| | `POST /v1/audio/speech` | 语音合成 |
| | `POST /v1/audio/transcriptions` | 语音识别 |
| | `GET /v1/models` | 模型列表 |
| **Anthropic** | `POST /v1/messages` | Claude 消息（流式事件转换） |

- **流式 SSE 逐行透传**，不缓冲、不截断，首 token 延迟做到最低；
- **工具调用、多模态字段**完整保留，content 结构不被破坏；
- Claude Code 可以直接连：`ANTHROPIC_BASE_URL` 指向网关，`ANTHROPIC_AUTH_TOKEN` 用网关发的 Key，模型全部映射到你的渠道池。

## 硬核点二：成本优先的三级路由

这是我最得意的一块。每个模型可以绑定多个上游，网关按 **计费层级** 调度：

```
免费层（free）→ 订阅层（subscription）→ 付费层（payg）
```

规则很简单：**有免费先走免费，免费挂了升订阅，订阅再挂才动付费**。

配合权重调度：同层级内按权重分配流量，高权重多发、低权重少发，避免单点过载。

实测效果：近 7 天 1943 个请求，2.3 亿 tokens，请求成功率 99.3%——其中相当一部分流量吃的是免费额度，付费账单肉眼可见地降了。

## 硬核点三：高可用，上游挂了不中断

这是跟 OneAPI 拉开差距的地方：

- **自动分流**：每个模型绑定多个上游，网关按计费层级、权重、健康度自动选择最优通道；
- **自动负载**：同层权重调度，避免单点过载；
- **自动重试**：上游失败自动切到同层下一个，整层失败自动升到下一计费层级——**不会因为任何一个上游故障导致请求中断**；
- **健康检查**：每上游独立探测，healthy / degraded / dead 三态；
- **快速失败熔断**：失败上游自动进冷却名单，后台定时探测自动恢复；
- **客户端断连保护**：客户端断连不误拉黑上游（这里踩过一个坑：6 个上游被误拉黑，已修复并加了回归测试）。

## 硬核点四：零配置文件，全数据库化

所有配置——上游、路由规则、折扣、API Key——全部存在 SQLite 里，页面 CRUD **即改即热重载**，不用重启、不用改 YAML、不用 reload。

管理页面是 Vue 2 CDN + 原生 HTML，无构建工具，离线可用。上游管理 / 路由规则 / 请求日志 / 请求统计 / API Key / 系统设置，六个 Tab 全可视化。

![API Key 管理：创建下游 Key，控制访问权限](../screenshots/api-keys.png)

**管理 API** 还带独立鉴权 key（`/api/admin/*`），AI 助手可以免登录动态改配置——这意味着你可以让 Agent 自己调路由、自己加渠道，真正把网关变成可编程基础设施。

## 硬核点五：极致的轻

- **单二进制**：Go 静态编译，零外部依赖，二进制 13MB，解压即用；
- **SQLite 存储**：`modernc.org/sqlite` 纯 Go 实现，无 CGO，WAL 模式 + 内存页缓存；
- **部署**：`docker compose up -d` 一行拉起，镜像 18MB；
- **无框架**：标准库 `net/http` 增强路由，不背框架包袱。

Docker 部署：

```bash
docker compose up -d --build

# 或直接跑二进制
./xuanji-server --port 8787 --db /path/to/xuanji.db
```

## 技术栈

- **语言**：Go 1.26+（标准库 `net/http` 增强路由，无框架）
- **存储**：SQLite（`modernc.org/sqlite` 纯 Go 无 CGO），WAL 模式 + 内存页缓存
