## 先说结论（不想看过程的直接看这里）

**1. 商汤 Lite 的综合能力 ≈ DeepSeek V4 Flash 的 96%，完全能打**

| 模型 | 最高得分 | 得分率 |
|------|---------|--------|
| DeepSeek V4 Flash（7/31 正式版） | 54/57 | **94.7%** |
| 商汤 sensenova-6.7-flash-lite | 53/57 | **93.0%** |

差 1 分，基本同级。**商汤官方没吹牛，Lite 型号确实够用。**

**2. 思考深度真的有区别，但"开满"不一定是好事**

| 思考档位 | DeepSeek V4 Flash | 商汤 Lite |
|---------|-------------------|-----------|
| 关闭思考 | 51/57 (89.5%) | 51/57 (89.5%) |
| low | 51/57 (89.5%) | **53/57 (93.0%)** |
| medium | — | 52/57 (91.2%) |
| **high** | **54/57 (94.7%)** | 52/57 (91.2%) |
| max | 53/57 (93.0%) | — |

**规律：**
- 关闭思考时，两个模型**一模一样**（都 51/57）——知识题全对，掉分全在逻辑推理
- 思考档位主要提升**逻辑推理**：DeepSeek 逻辑题从 none 的 10/13 升到 high 的 12/13
- DeepSeek **high 是最优档**，max 反而掉 1 分（过度思考把对的改错了）
- 商汤 **low 是最优档**，medium/high 反而掉（代码题从 5/6 掉到 4/6）

## 测试方法说明（别人可以复现）

- **题目**：57 道客观题，覆盖中医（10）、养生（6）、玄学（8）、生活常识（6）、逻辑推理（13）、数学（8）、代码（6）
- **客观性**：全部是**有标准答案**的判断题/选择题/数值题；代码题**真实运行验证**（不是模型自评，是 Python 跑测试用例）
- **可复现**：temperature=0，每模型每档位独立调用，所有题一次跑完
- **测试环境**：DeepSeek 走官方上游直连（opencode.ai zen/go，7/31 正式版）；商汤走本地网关路由（3 个 API key 负载均衡，避免免费额度 429 限流）

### 测试脚本

评测脚本已开源在项目 tools/ 目录：
- `eval_models.py` — 单次评测（57 题，支持 `--effort none/low/medium/high/max` 控制思考深度）
- `eval_models_run.py` — 多轮汇总取均值

```bash
# 测商汤 Lite（走本地网关，多 key 负载均衡防 429）
python3 eval_models.py --base http://127.0.0.1:3002 --key <璇玑key> \
    --models sensenova-6.7-flash-lite --effort low --workers 3

# 测 DeepSeek 正式版（直连官方）
python3 eval_models.py --base https://opencode.ai/zen/go/v1 --key <上游key> \
    --models deepseek-v4-flash --effort high --direct
```

## 踩坑记录（给后来人）

1. **商汤是思考模型**：响应里有 `reasoning` 字段，`max_tokens` 给太小会全部被思考吃掉导致 `finish_reason=length` 空回复 → **max_tokens 给 6000+**
2. **商汤免费额度并发敏感**：6 并发瞬间 429 → 走本地网关多 key 负载均衡，或 workers=3
3. **思考控制参数**：
   - 商汤：`thinking: {type: "disabled"}` 关思考；`output_config: {effort: "low/medium/high"}` 控制强度
   - DeepSeek：`thinking: {type: "disabled"}` 关思考；`reasoning_effort: "low/high/max"` 控制强度
4. **opencode.ai 拦 Python-urllib UA** → 请求头带浏览器 UA
